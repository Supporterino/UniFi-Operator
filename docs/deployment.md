# Deployment

This is the canonical deployment reference for UniFi-Operator. Two paths are supported and must
stay consistent: **kustomize** (the kubebuilder default, under `operator/config/`) and **Helm**
(under `charts/`).

## Which to use

- **Kustomize** — canonical for development and for the operator's own resources. `make deploy`
  from `operator/` installs CRDs and the manager.
- **Helm** — packaged distribution for consumers who deploy with `helm install`. The chart must
  render the same core objects as kustomize.

Keep the two in sync: a change to RBAC, the manager deployment, or CRDs updates both.

## Operator (kustomize)

```bash
cd operator

# Install CRDs only
make install

# Build and push the manager image
make docker-build docker-push IMG=<registry>/unifi-operator:<tag>

# Deploy the manager
make deploy IMG=<registry>/unifi-operator:<tag>

# Undeploy
make undeploy
make uninstall
```

The kustomize root is `operator/config/default`. `operator/config/crd`, `config/rbac`, and
`config/manager` are generated/reference layers — do not hand-edit generated RBAC; change the
`+kubebuilder:rbac` markers and re-run `make manifests`.

### Configuration

Credentials are per-connection, not process-wide. The manager consumes no environment or flag
credentials: each `UnifiController` references a same-namespace `Secret` through
`spec.secretRef` (`name` + `key`), and the operator resolves the key at reconcile time. Never
accept an inline API key, bake credentials into the Deployment manifest, or write them to
`status`, events, or logs — reference a `Secret` instead. TLS verification is on by default;
`spec.insecureSkipVerify` is the explicit, documented opt-out for a self-signed console (see
[Security](security.md)).

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: unificontroller-api-key
type: Opaque
stringData:
  api-key: <redacted>
```

```yaml
apiVersion: unifi.supporterino.de/v1alpha1
kind: UnifiController
metadata:
  name: unificontroller-sample
spec:
  url: https://unifi.example.com
  secretRef:
    name: unificontroller-api-key
    key: api-key
  insecureSkipVerify: false
```

## Helm

```bash
helm lint charts/unifi-operator
helm template unifi-operator charts/unifi-operator -f charts/unifi-operator/values.yaml
helm upgrade --install unifi-operator charts/unifi-operator \
  --namespace unifi-operator --create-namespace \
  --set image.repository=<registry>/unifi-operator --set image.tag=<tag>
```

Chart values expose the image, replicas, resource requests/limits, and the RBAC toggle. The
manager consumes no environment credentials: each `UnifiController` resolves its API key from the
`Secret` named in `spec.secretRef`.
There is no CRD-install value: CRDs ship in `charts/unifi-operator/crds/` and Helm installs them on
the first `helm install` only (pass `--skip-crds` to skip). Document every value in
`charts/unifi-operator/values.yaml`.

## CRDs

- CRDs live in `operator/config/crd/` and are re-generated by `make manifests`. Never edit them
  by hand.
- Helm ships the same CRDs under `charts/unifi-operator/crds/`, installed on first install only.
  To diff the chart's CRDs against the kustomize output, run
  `helm template unifi-operator charts/unifi-operator --include-crds` (plain `helm template`
  omits `crds/`) and compare against `operator/config/crd`.
- CRD version changes follow the hub/spoke conversion pattern; see [CRD conventions](crd-conventions.md).

## Upgrade and compatibility

- Add fields; deprecate before removing.
- A new CRD version is served alongside the old one during migration.
- The operator and CRDs are upgraded together. `helm upgrade` does not upgrade the files under
  `crds/`, so apply the regenerated CRDs explicitly
  (`kubectl apply -f operator/config/crd/bases/...`) before the new manager rolls out. On the Helm
  path, apply CRDs first and then run `helm upgrade --skip-crds` (or use the kustomize
  `make install`).

## Observability

- Ship metrics on the standard controller-runtime endpoint and scrape with a `ServiceMonitor`
  where available.
- Emit Kubernetes events for significant reconcile outcomes so `kubectl describe` is useful.

## Gate

Any manifest change passes:

```
kustomize build operator/config/default
helm lint charts/<chart> && helm template <name> charts/<chart> -f charts/<chart>/values.yaml
```
