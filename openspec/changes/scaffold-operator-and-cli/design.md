## Context

See [proposal.md](proposal.md) — Why. The workspace currently has no Go code: `operator/` and
`cli/` contain only `AGENTS.md`, and `charts/`, `operator/config/` do not exist. The module
layout is dictated by the wrapped-directory decision (`operator/`, `cli/`, `docs/`) and the
root `AGENTS.md` Cross-Module Change Checklist.

Constraints that shape the approach:

- Go 1.27 and kubebuilder are available locally; `envtest` assets are fetched by
  `setup-envtest` on first `make test`.
- The CRD contract rules in `docs/crd-conventions.md` and the endpoint contract in
  `docs/unifi-api.md` are already defined and must not regress.
- The docs gate (`zensical build --strict`) is live and must stay green.

## Goals / Non-Goals

**Goals:**

- A kubebuilder-standard `operator/` module that passes `go build/vet/lint/test` and
  `make manifests generate` with no diff.
- One conformant sample CRD (`UnifiNetwork`) that demonstrates the CRD golden rule end to end:
  markers → generated CRD → reconciler → status conditions.
- A separate `cli/` Go module with a working cobra command tree and a snapshot stub.
- Kustomize and Helm deployment paths that both render the manager, RBAC, and CRDs.

**Non-Goals:**

- Real UniFi controller connectivity (the client is a fixture-backed stub).
- Additional CRD kinds, conversion webhooks, or OLM bundles.
- CI wiring; the gates are made runnable locally, not yet wired into `.github/workflows`.

## Decisions

**Adopt kubebuilder's canonical project scaffold inside `operator/`.** Run `kubebuilder init`
and `kubebuilder create api` so `cmd/`, `api/v1alpha1/`, `internal/controller/`, `config/`,
and the generated `Makefile` match what `operator/AGENTS.md` documents. Alternative: hand-roll
the manager — rejected because it would diverge from every kubebuilder convention the docs and
agents assume.

**Module path `github.com/Supporterino/UniFi-Operator/operator` (and `.../cli`).** The GitHub
remote is `github.com/Supporterino/UniFi-Operator`; per-module paths keep the two modules
independent while sharing a repository prefix. Alternative: a single module with `cli` as a
subpackage — rejected because the CLI must be a separate module so it does not pull the
operator's controller-runtime dependency tree.

**Keep the UniFi client behind an interface returning plain structs.** `internal/unifi` defines
a client interface and a fixture implementation; no Kubernetes types cross the boundary. This
lets the reconciler and tests exercise the contract without a live controller and preserves the
module boundary rule in `AGENTS.md`.

**Single API version `v1alpha1`.** No conversion webhook in the scaffold. Versioning is added
only when required by a real schema change, per `docs/crd-conventions.md` Rule 5.

**Ship both kustomize and Helm from the start.** Kustomize (`operator/config/`) is generated by
kubebuilder; the Helm chart (`charts/unifi-operator/`) is authored to render the same core
objects. Alternative: Helm only — rejected because kubebuilder's generated kustomize is the
canonical dev path and `make deploy` depends on it.

## Risks / Trade-offs

- **envtest binary download on first `make test`** → document `KUBEBUILDER_ASSETS` and the
  `setup-envtest use -p path` fallback in `operator/AGENTS.md` (already noted); CI can cache it.
- **Kustomize and Helm drift over time** → keep the Helm chart's manager/RBAC aligned with
  `operator/config/` and verify with `helm template` against the kustomize output during review.
- **A stubbed UniFi client could entrench a wrong contract** → keep `docs/unifi-api.md` the
  source of truth and mark the stub explicitly; real integration replaces the fixture
  implementation without changing the interface.
- **golangci-lint config may not exist** → add a minimal `.golangci.yml` so the lint gate is
  defined and reproducible; keep the enabled linters conservative.

## Migration Plan

No migration: this is additive scaffolding. Rollback is reverting the change; no existing
behavior is modified. `openspec/specs/project-scaffold/spec.md` becomes the main spec on
archive.

## Open Questions

None blocking. The exact UniFi endpoints the stub will eventually implement remain deferred to
a follow-up change and are tracked in `docs/unifi-api.md`.
